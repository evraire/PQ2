HTML

Hyper Text Markup Language (HTML) is the standard language used for creating Web pages. An HTML file is a plain text file identified with an .html extension (e.g. programmers_quest.html) that marks up text with tags to add structure, formatting and links to it. The tags tell the browser how to display the content of the page.

Any text editor can be used to create a Web page, but a Web browser such as Firefox or Chrome is needed to properly view them formatted. To create a new Web page, start from the folder where you want to save it and right-click then select...

  • Linux: Create New → Text File...
  • Windows: New → Text Document

Give it a file name that ends with the .html extension, then open it in your favourite text editor. To see the effects of changes made to the code in your HTML file be sure to save them in your text editor then Reload your page in the browser by clicking the ⟳ icon, or using the F5 or Ctrl+R shortcuts.

If your Web page isn't displaying the way you were expecting then it could indicate that there's an error in your code somewhere. Web browsers come with Developer Tools, the most useful of which to find HTML errors being the DOM Inspector. You can open them from your browser's menu under: More tools → Web Developer Tools, or by using the F12 or Ctrl+Shift+I shortcuts.

Note that you can view the HTML of any Web page by right-clicking on it and selecting View Page Source or using the Ctrl+U shortcut.

Elements

An element in HTML typically consists of a start tag, the content it affects and an end tag. Note that a few elements are empty elements so have no content and only use the start tag. A basic start tag consists of a less than character (e.g. <), the element's name and a greater than character (e.g. >). The corresponding end tag consists of a less than character, a slash (e.g. /), the same name and a greater than character. While element name are case-insensitive, meaning they can use upper or lowercase characters, the modern Web typically uses all lowercase ones. For example, the p element is used to surround a paragraph of text:

{% highlight html %}

This is a paragraph.

{% endhighlight %}

Elements can be nested, meaning they can contain other elements. Note that, when elements are properly nested, the inner element must end before the outer one. For example, the b element tells the browser to render its content using a bold font. Note how it is nested within the paragraph element so its end tag appears before the paragraph's one:

{% highlight html %}

This paragraph has some bold text in it.

{% endhighlight %}

Attributes

Start tags can have one or more attributes in them that are used to provide additional details. They appear between the element's name and the greater than character that closes the tag, and are separated by a space. They take the form of a name/value pair that consists of the attribute's name, an equal sign (e.g. =) followed by the attribute's value usually enclosed in double-quotes (e.g. "). For example, links are created using the a element and its href attribute specifies the address that the link points to:

{% highlight html %}

Link to the Programmer's Quest site.

{% endhighlight %}

Comments

Like every other programming language, HTML supports comments that are used to make the code more understandable, but aren't shown in the Web page. Comments begin with a less than character, an exclamation mark and two dash characters (e.g. <!--), then continue until two dashes and a greater than character are encountered (e.g. -->). Everything in between gets ignored by the browser, including any elements.

A Question of Semantics

When authoring content for the Web it is important to be inclusive so that everyone can enjoy your work. For Web pages this means keeping in mind that the visually impaired may not be able to see the formatting on your page: many of your users will experience your content using a screen reader instead of a Web browser.

Historically, formatting-only elements used to cause issues with screen readers as they didn't know how to interpret them, and certainly couldn't display the format. This sometimes caused the meaning of a sentence to change and resulted in user confusion.

Consider the following example:

He's a special boy.


He's a special boy.

When reading the first sentence it sounds like the boy is genuinely special. However, by putting emphasis on the word special, the second one reads differently, which makes it sound sarcastic and completely changes the meaning of the sentence.

Here's another example where the formatting doesn't necessarily change the meaning of the sentence, but can change how it is read: 

Whatever you do, do not be late!

The formatting strongly emphasizes important words and we tend to stress these when reading the sentence out loud.

To better support screen readers and the visually impaired semantic elements were introduced to HTML that convey the meaning of the formatting and allow screen readers to read out sentences as they were intended. For backwards compatibility the formatting-only tags can still be used, although for formatting text without conveying any meaning it is generally preferred to use a span element with CSS styling.

In general, if a sentence reads differently when formatted then you should use a semantic element. When unsure it is generally preferable to favour a semantic element over the formatting-only one.

Document

An HTML document follows a prescribed structure that identifies a file as HTML and divides it into two major sections: the head element for meta information about the content such as its title and the language it is written in, and the body element that has the actual content of the page to display.

New HTML documents start from this template:

{% highlight html %} [Page Title] [Page Content] {% endhighlight %}

All HTML files must begin with a document type declaration followed by the html element, which tell Web browsers to interpret the content of the file as formatted text when displaying it to the user. The document type declaration is a special empty element that doesn't have an end tag. It can be seen in the template above and looks like this:

{% highlight html %}{% endhighlight %}

As mentioned, it is immediately followed by the html element that wraps the entirety of the content, so its closing tag ends up as the last thing in the file. While not strictly necessary, it is recommended to add the lang attribute to it to specify the language the page content (not the code!) is written in. The value of the lang attribute follows a specific pattern: it must begin with a two letter lowercase language code for the language, optionally followed by a dash (e.g -) and a two letter uppercase country code for the country. For example:

  • <html lang="fr"> indicates that the Web page is in the French language;
  • <html lang="en"> indicates English content;
  • <html lang="en-CA"> indicates that the language used is English Canadian.

As seen in the template above, the html element always contains a head element followed by a body element.

head

In the template above the head element also contains two elements.

The first one is the meta element. While there's only one listed here, head elements can often be found with many of them each with their own purpose. While these elements are optional, the one seen here is recommended for specifying the character set of the file using the charset attribute and should come first in the head. The character set is set by your text editor when saving your code, and nearly every modern text editor uses the utf-8 one by default.

The second element under the head in the template is the title element, which is typically set to the title of your Web page but can be whatever you want. The content of the title element is the text shown in your browser's tab and is used for the default name of bookmarks to your page.

The head element can contain other important elements not shown in this template. The style element is used to add an internal Cascading Style Sheet (CSS) directly within the HTML file, while the link elements are used to reference external style sheets with a .css extension. Similarly the script elements are used both for internal JavaScript scripts as well as external ones with a .js extension.

Note: Cascading Style Sheets (CSS) and JavaScript are outside the scope of this document.

body

The body element contains all the text and markup that gets displayed to the user in the Web browser. Note that, in HTML documents, white space is insignificant: no matter how many spaces are inserted or how much your content is indented it gets collapsed down to a single space for display. This has the benefit of allowing you to space out your code to make it easier to read without affecting how the user will see the page.

The top level of the body's content typically contains elements used to structure the page's content into headings, paragraphs, lists, tables and forms.

Structural Elements

Headings

Most real world texts are structured into headings and paragraphs, which makes reading them more enjoyable. Text can have multiple levels of headings: consider a book whose main heading could be its title, with each chapter having its own heading and can sometimes have sub-chapters with their own heading too.

HTML has six heading elements: h1, h2, h3, h4, h5 and h6. Each element is used for a different level with h1 being for the main heading, h2 for a subheading, h3 for a sub-subheading, and so on. It is preferable not to skip a level as web browsers generally expect to encounter an h1 heading before an h2 one, and an h2 heading before an h3 one.

Note how this conveys semantic meaning between the heading levels: higher numbered headings usually fall under lower numbered ones, and headings with the same number usually have the same importance. Users often skim a page by its headings, and search engines will use them when indexing your Web page.

The look of each heading level can be highly customized using CSS styling, but by default lower numbered headings with higher importance get displayed in a larger font. Each subsequent level of heading gets displayed using smaller and smaller ones:

Paragraphs and Line Breaks

Paragraphs always start on a new line and are usually a block of text. Every block of text on this page is an example of a paragraph. If for whatever reason you need to introduce a line break in a specific location you can use the empty br element for that. Remember: empty elements don't have an end tag! For example:

{% highlight html %}

Mozilla
331 E. Evelyn Avenue
Mountain View, CA
94041
USA

{% endhighlight %}

This is displayed in the browser like this:

Mozilla
331 E. Evelyn Avenue
Mountain View, CA
94041
USA

Lists

An unordered list list, often called a bullet list, is defined using the ul element, with each list item starting with an empty li element. For example:

{% highlight html %}
  • An item
  • Another item
  • Some other item
{% endhighlight %}

This is displayed in the browser like this:

  • An item
  • Another item
  • Some other item

Similarly an ordered list is defined using the ol element and uses the same li empty element for each item:

{% highlight html %}
  1. First item
  2. Second item
  3. Third item
{% endhighlight %}

This is displayed in the browser like this:

  1. First item
  2. Second item
  3. Third item

Lists can be nested resulting in the inner list getting indented. Unordered and ordered lists can be used together:

{% highlight html %}
  • An item
  • Another item
    1. First item
    2. Second item
    3. Third item
  • Some other item
{% endhighlight %}

This is displayed in the browser like this:

  • An item
  • Another item
    1. First item
    2. Second item
    3. Third item
  • Some other item

section and div

It can be desirable to group elements together to organize them, such as grouping a chapter heading with all of its paragraphs. HTML has the section and div elements for this, with the former being the semantic element and the latter having no meaning. By default this doesn't change the look of its content, but CSS styling can be applied to the group to affect all of the elements within. It can also be useful when using JavaScript to affect everything within a group together.

Formatting Elements

em and i

To add emphasis to text by displaying it in italics there are the em and i elements, with the former being the semantic version of the latter. Using the previous sentence as an example:

For the reasons mentioned above it is preferable to use the semantic version. However, if you just want to render text in italics without intending the sentence to read differently, it is preferable to use the span element.

strong and b

To emphasize the importance of text by displaying it in bold HTML has the strong and b elements, with the former being the semantic version of the latter.

For the reasons mentioned above it is preferable to use the semantic version. However, if you just want to render text in bold without intending the sentence to read differently, it is preferable to use the span element.

span

If you need to format text without putting any emphasis on it and changing the way the sentence reads it is preferable to use the span element along with its style or class attributes and CSS styling. For example:

Images get added to a Web page using the empty img element. It needs to have a src attribute set to the address of the image to display. It also needs an alt attribute, which has the double role of getting read by screen readers and getting shown to users when the link to the image is broken.
